# 截图拍摄清单

README 里三处 `📸 截图待补` 占位对应下面三张图。拍完后把文件放进本目录，再把 README 对应那行占位替换成 `![说明](docs/img/文件名.png)`。

**统一前提**

- 浏览器窗口宽度 ≥ 1440px（右侧 Sidekick 固定 420px，窄了会挤）。
- 先打开 <https://orbit-os.pages.dev>（或本地 `npx wrangler pages dev`），确保 Sidekick 顶部**没有**「录播模式」黄色角标——录播模式截图会被面试官问到，能拍真的就拍真的。
- 顶栏「重置演示数据」可以把数据恢复到 `generateSeed(42)` 初始态，拍砸了就点它重来。
- 截图前把浏览器缩放调回 100%，隐藏书签栏。

## 1. `dashboard-risk.png` — 仪表盘与主动风险卡

- **页面**：`/`（仪表盘）
- **角色**：顶栏切到 **供应链主管**（王强）
- **画面必须出现**：
  - 顶部红色（`high`）风险卡，标题 **「2 张订单存在交期风险」**，副标题 **「SKU-203 高精度伺服电机 SV-800 缺口 48 台，最早到货 2026-09-16」**，右侧有「让 Agent 排查 →」按钮
  - 四张 KPI 卡：本月营收（供应链角色显示 `***`，这是脱敏的可见证据，别切成别的角色）、待发货订单、**交期风险订单 = 2**、逾期应收（显示 `—` 仅销售总监 / CEO 可见）
  - 下方三张图表（商机漏斗 / 订单状态饼图 / 12 周发货趋势）
- **注意**：看板每 4 秒会自动推进一条数据，KPI 数字会跳。要拍就趁「交期风险订单」仍为 2 时拍（埋雷订单被 tick 排除，这个数不会自己变）。
- **可选**：另拍一张 `dashboard-risk-cleared.png`，在演示批准采购单之后，风险卡消失、KPI 变 0，两张并排能讲清「Agent 干预 → 看板变化」的因果。

## 2. `sidekick-running.png` — 规划清单与工具调用卡

- **页面**：任意页（建议仍停在仪表盘），焦点在右侧 Sidekick
- **角色**：供应链主管（王强）
- **操作**：点风险卡的「让 Agent 排查 →」，或点 Sidekick 底部第一个预设问题「未来两周要交付的订单有风险吗…」
- **画面必须出现**：
  - Sidekick 顶部状态行 **「王强 · 供应链主管 · 可用工具 8 个」**
  - 规划清单：`goal` + 3～5 条步骤，其中至少一条已打勾（`done`）、一条正在跑（`running`，转圈）
  - 至少一张**已展开**的工具调用卡，露出 `simulate_delivery_risk` 的入参 `{"withinDays": 14}` 和出参 JSON 里的 `"gap": 28` / `"riskLevel": "high"`，以及卡片右上角的耗时（如 `4ms`）
- **拍摄技巧**：工具卡默认折叠，点一下卡片标题才展开。Agent 跑得快，可以等它跑完再展开工具卡补拍——清单会全部打勾，但工具入参/出参更完整，也可以接受。

## 3. `sidekick-confirm.png` — HITL 确认卡

- **页面**：同上，Sidekick 内
- **角色**：供应链主管（王强）
- **操作**：接着上一步往下跑，Agent 走到 `create_purchase_order` 时会自动停下弹卡
- **画面必须出现**：
  - 黄色边框卡片，左上角 **「需要你确认」** + 灰色小字工具名 `create_purchase_order`
  - 摘要全文可读：**「将向【锐驰机电】采购 SKU-203 高精度伺服电机 SV-800 × 48 台，预计成本 ¥591,360，预计到货 2026-09-07（加急）」**
  - 底部「批准执行」「拒绝」两个按钮（**在点击之前**截图，点完按钮就变成结果状态了）
- **可选**：另拍 `sidekick-final.png`，批准后的结论段落，里面 `[[SO-2026-0428]]` `[[SKU-203]]` `[[PO-2026-955]]` 被渲染成蓝色可点击 chip——这是「数字可溯源」最直观的一张图。
